# Termo — NodeMCU ESP-12F, веб-интерфейс

Проект поддерживает только ESP8266 на плате NodeMCU ESP-12F.
Профиль PlatformIO: `nodemcuv2`, 4 МБ Flash.
Экран и энкодер отключены; оставьте `TERMO_LOCAL_DISPLAY 0`.

| Сигнал | NodeMCU |
| --- | --- |
| DATA датчика DS1820 / DS18S20 / DS18B20 | D5 (GPIO14) |
| VDD датчика | 3V3 |
| GND датчика | G (GND) |
| IN релейного модуля, совместимый с 3,3 В | D6 (GPIO12) |

Между DATA и 3V3 нужен резистор 4,7 кОм. GPIO работают с 3,3 В.
Питание релейного модуля зависит от его модели; катушку к GPIO не подключают.
Для реле с активным LOW установите `pumpRelayActiveHigh = false` в `src/main.cpp`.
Период усреднения сохраняется в эмулированной EEPROM; история остаётся в RAM.
После перезапуска реле выключено.

```text
pio run
pio run --target upload --upload-port COM9
pio device monitor --port COM9 -b 115200
```

## Настройка Wi-Fi и открытие интерфейса

1. Скопируйте `include/NetworkConfig.example.h` в `include/NetworkConfig.h`.
2. В новом файле заполните `TERMO_WIFI_SSID` и `TERMO_WIFI_PASSWORD`
   для домашней сети **2,4 ГГц**. Файл исключён из Git. Пароль не выводится в лог.
3. Соберите и загрузите прошивку через PlatformIO. Откройте Serial Monitor
   на скорости 115200. После подключения появятся IP и MAC устройства.
4. Откройте `http://<IP>/` с телефона или компьютера в той же сети.
   Также доступно `http://termo.local/`, если клиент поддерживает mDNS.
5. Для постоянного IP создайте DHCP reservation в роутере по MAC устройства.
   Адрес выдаёт роутер; прошивка не задаёт произвольный статический IP.

Страница встроена в прошивку, внешние сайты и интернет ей не нужны.
Сервер использует штатную библиотеку ESP8266WebServer.
Обработка медленного HTTP-клиента может задерживать кооперативный цикл;
это не реализация с жёсткими гарантиями времени.
Она обновляет показания каждые 2 секунды, позволяет сохранить период среднего
от 1 до 60 минут и вручную включить/выключить выход реле насоса.
Уставка и автоматическое регулирование пока отсутствуют.
Выход после перезапуска выключен, ручное состояние не сохраняется.
При потере Wi-Fi измерения продолжаются, выход сохраняет последнюю команду;
устройство пытается восстановить соединение. При потере связи страница
показывает неизвестное состояние и отключает кнопки.

Если Wi-Fi не настроен, измерения всё равно работают, а Serial сообщает,
что нужно заполнить конфигурацию. Открытая точка доступа не создаётся.
Доступ к управлению есть у устройств вашей локальной сети; пользовательской
авторизации и HTTPS пока нет. Заголовок управления защищает от отправки команд
со сторонних веб-страниц, но не служит паролем. Не открывайте порт в интернет.

API: `GET /api/status`, `POST /api/average` (`minutes=1..60`),
`POST /api/pump` (`on=0|1`). Для POST нужен заголовок `X-Termo-Control`
со значением `controlToken` из статуса. Невалидные значения возвращают 400,
отсутствующий заголовок — 403, ошибка сохранения периода — 500.
При отсутствии измерения JSON содержит `null`, а не `NaN`.
